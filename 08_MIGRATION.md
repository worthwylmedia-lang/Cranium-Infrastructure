# Cranium Migration Chapter

**Binder-Grade • Authority-Bound • Dual-Engine • Governance Substrate**

This chapter defines the complete, disciplined migration path from the legacy Cranium ecosystem to the curated acquisition-facing infrastructure surface. It integrates the structural validation matrix, the authority invariant, the category definition, the research paper, and the audit findings into a single operational plan.

It is designed to ensure:

- no accidental exposure
- no credential leakage
- no premature migration
- no contamination of the clean account
- no loss of provenance
- no breakage of the authority invariant
- no ambiguity in the Kernel lineage

This is the migration path for governed infrastructure.

## 7. Final Migration Gate: Kernel Pin Reconciliation

The audit identified a documentation discrepancy that must be resolved:

- Verified Kernel pin: 0d0ae41f78e3f23da073390285d401c4a215dc6a
- Older IP-boundary references: c2bd6d3 and 482b9c54a80f0894e523cb94c77fa85d3f62c264

The binder must:

- update current authoritative references to 0d0ae41f78e3f23da073390285d401c4a215dc6a
- preserve older pins as historical lineage
- ensure no document implies multiple current Kernel revisions

This is a documentation-integrity gate, not permission to rewrite historical records.

## 8. Final Migration Gate: ChromiumOS Boot Evidence

The Chromium Edition evidence boundary remains explicit:

- architecture: PASS
- integration: PASS
- build scripts: PASS
- bootable image: PENDING
- runtime validation: PENDING
- verified-boot evidence: PENDING

These states must remain distinct in acquisition materials.

This is the difference between:

> We built the architecture.

and:

> Here is the machine booting it.

The first is architecture evidence. The second requires executable image and runtime evidence.

## 10. Final Migration Acceptance Rule

Migration acceptance requires a clean acquisition surface, preserved provenance, separated credentials, reconciled current Kernel lineage, bounded claims, and no unresolved FAIL state in the structural validation matrix.

PENDING evidence may remain only when the limitation is explicit and the material does not represent the pending state as verified.

The Kernel remains the sole canonical authority source throughout migration.
