# Demonstrations

Demos must show the separation between proposal, assessment, authority, execution, receipt, continuity, and recovery.

## Core Sequence

1. Commander presents identity and system state.
2. A user intent is captured.
3. Cranium AI produces a bounded proposal.
4. Synapse assesses relevant evidence and trust conditions.
5. Kernel issues or denies the governed authority transition.
6. Commander executes only an authorized transition.
7. A receipt records the governed result.
8. Miracle Memory records permitted continuity.
9. Circuit Breaker / COMA demonstrates containment and recovery where applicable.

## Negative Paths

Demonstrations should include denied authority, replay rejection, evidence tampering, stale-session fencing, and recovery without implying that a blocked operation completed.

ChromiumOS boot and runtime demonstrations remain pending until the supported x86-64 build and runtime acceptance gates are completed.
